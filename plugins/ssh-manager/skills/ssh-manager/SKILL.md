# SSH 管理

使用 `ssh-manager` MCP 工具，优先使用已保存的服务器配置。不要再次询问用户服务器地址、登录账户或密码。

## 核心规则

服务器别名支持中文，例如：生产服务器、测试环境、客户服务器。

1. 每次调用远程操作工具前，必须先输出一句简短中文话术，告诉用户接下来对哪台服务器做什么。
2. 即使当前是“默认执行”或“会话免确认”，也必须先说明再执行，不能静默调用。
3. 话术只保留关键信息：服务器、操作、路径或命令目的，通常一句话即可。
4. 开始远程操作前，先调用 `ssh_profile_list`，除非用户已经明确给出服务器别名。
5. 如果匹配到多个服务器，询问用户选择哪个别名；不要询问服务器地址、账户或密码。
6. 如果还没有保存服务器，调用 `ssh_profile_upsert`。MCP 服务会打开安全表单填写凭据。不要让用户在聊天中发送密码或私钥口令。
7. 不要绕过本插件直接调用系统的 `ssh`、`sftp` 或 `plink`。
8. 只有工具返回成功状态后，才能告诉用户操作完成。失败、拒绝、超时或部分失败都必须如实说明。
9. 如果确认结果为拒绝，立即停止操作，并说明远程服务器没有发生任何变更。

## 执行前话术示例

只读检查：

```text
正在检查 `生产服务器` 的 Nginx 状态。
```

连接测试：

```text
正在测试 `生产服务器` 的 SSH 连接。
```

上传：

```text
正在把 `E:\project\dist` 上传到 `生产服务器:/srv/app`。
```

部署：

```text
正在部署到 `生产服务器:/srv/app`，完成后重启 nginx。
```

下载：

```text
正在从 `生产服务器:/srv/app/logs` 下载日志。
```

删除配置：

```text
正在删除本机保存的 `测试服务器` SSH 配置。
```

不要把话术写成长篇解释。用户没有追问时，说明一句后直接执行。

## 输出取用规则

调用返回的正文结构固定为：命令回显（`$ 命令`）→ 摘要 → `输出：` 段。

- `ssh_exec` 的结果在「输出：」段；段首是 `exit=N`。看到 `（无输出）` 说明命令本身没有输出，不是回传丢失。
- 需要完整输出（被截断、或要回溯历史）→ 调用 `ssh_log_read`：
  - `since: "30m"` 只看最近半小时；`full: true` 取未截断的 stdout/stderr；`onlyErrors: true` 只看失败。
- 超时：只读命令默认 30 秒、变更类默认 120 秒，返回里的 `timeoutSeconds` 是实际生效值。
- 长命令（构建、重启）可以让用户在实时操作面板里看进度：`ssh_exec` 默认把输出流式推送到面板（`stream: false` 可关）。
- 失败后是否可重试看返回里的 `retryable`（只读为 true，变更/破坏性为 false，不要自动重试）。
- 批量或交互式操作 → 用 `ssh_terminal_*`。
- 文件传输与校验 → `ssh_upload` / `ssh_download`（返回里的 `verified` 表示校验是否一致，上传不一致会自动重传一次）。
- 部署后需要执行命令 → `ssh_deploy`，postCommand 的输出以「部署后命令 stdout/stderr」分组显示。
- 失败时正文会给出「失败类型」「建议」和原始 stdout/stderr，不必再去猜。

## 工具说明

- `ssh_profile_list`：列出服务器别名和非敏感连接信息。
- `ssh_vault_status`：查看本地仓库位置、保护方式、操作模式和配置数量。
- `ssh_session_open`：为指定服务器打开 OpenSSH 远程命令长连接和 SFTP 长连接。
- `ssh_session_close`：关闭指定服务器的 OpenSSH 持久连接。
- `ssh_session_status`：查看当前 OpenSSH 持久连接。
- `ssh_session_register`：为当前任务注册可切换的 SSH 操作会话。
- `ssh_set_approval_mode`：切换本次会话的操作模式。
- `ssh_operation_dashboard`：打开、查看或停止 SSH 实时操作面板。
- `ssh_log_read`：读取本地操作日志。日志为 JSONL，已自动脱敏，包含每次调用的参数、耗时、结果、失败类型和原始 stdout/stderr。排查失败时优先用它。
- `ssh_terminal_open`：打开持续连接的交互式 SSH 终端。
- `ssh_terminal_write`：向交互式 SSH 终端发送输入。
- `ssh_terminal_read`：读取交互式 SSH 终端的新输出。
- `ssh_terminal_close`：关闭交互式 SSH 终端。
- `ssh_terminal_list`：列出当前交互式终端。
- `ssh_profile_upsert`：通过安全表单添加或更新服务器、账户和凭据。
- `ssh_profile_remove`：删除本地 SSH 配置。
- `ssh_test_connection`：使用保存的凭据执行无害连接测试。
- `ssh_exec`：执行远程命令。调用时必须提供简短的 `purpose`。
- `ssh_upload`：使用 SFTP 上传本地文件或目录。调用时必须提供简短的 `purpose`。
- `ssh_deploy`：上传文件或目录，并可选执行部署后命令。调用时必须提供简短的 `purpose`。
- `ssh_download`：使用 SFTP 下载远程文件或目录。调用时必须提供简短的 `purpose`。

## OpenSSH 持久连接

用户要求“长连接”“复用 SSH 连接”或“不要每次重连”时：

1. 调用 `ssh_session_open`，传入服务器别名。
2. 连接建立后，`ssh_exec`、部署后命令、上传和下载会自动复用长连接。
3. 调用 `ssh_session_status` 查看当前长连接。
4. 用户要求关闭时调用 `ssh_session_close`。

Windows OpenSSH 不支持 `ControlMaster`，这里分别保持常驻 OpenSSH 远程 shell 和常驻 `sftp` 进程：远程命令走长连接 Shell，上传和下载走同一 SFTP 长连接。

## 操作模式

- `默认执行`：只读命令无需确认，直接执行；上传、下载、部署、删除和变更命令仍会确认。
- `只读免确认`：只允许执行只读命令，变更类操作会被阻止。
- `会话免确认`：仅在用户明确要求“开启本次会话免确认”时使用；切换后本次 MCP 会话内所有操作直接执行。

默认执行模式下，敏感操作的确认表单提供两个选项：“确认本次执行”和“确认并开启本次会话免询问”。用户选择第二项后，当前操作立即执行，并让本次会话的后续敏感操作免询问。不要替用户选择第二项。

切换模式时调用 `ssh_set_approval_mode`。不要主动把模式切换为 `会话免确认`，必须由用户明确要求。

## 只读检查流程

```text
先输出一句“正在检查……
ssh_profile_list -> 选择别名 -> ssh_exec 执行单条只读命令
```

只应把严格白名单中的单条只读命令作为无确认操作。日志、配置文件、环境变量、密钥文件、删除、写入、重启、安装包、修改权限等敏感读取或变更，必须遵守当前操作模式。

## 部署流程

1. 先输出一句“正在部署到……
2. 使用本地绝对路径。
3. 调用 `ssh_deploy`，传入 `localPaths`、`remoteDirectory`、可选的 `postCommand` 和简短 `purpose`。
4. 默认模式下，等待用户确认后再执行；会话免确认模式下，直接执行。
5. 完成后用一句中文报告结果。

## 远程变更流程

1. 先输出一句“正在对……执行……
2. 每次尽量只放一条明确的远程命令。
3. 调用 `ssh_exec`，传入 `command` 和 `purpose`。
4. 默认模式下，等待用户确认后再执行；会话免确认模式下，直接执行。
5. 如果工具返回拒绝或错误，停止操作并报告。

## 实时操作面板

用户要求“实时显示 Codex 对服务器的操作”或“按会话查看操作”时：

1. 先调用 `ssh_session_register`，用一句简短的会话名称描述当前任务，例如“生产服务器维护”。
2. 调用 `ssh_operation_dashboard`，`action` 使用 `打开`。
3. 工具会返回本机面板地址。
4. 如果当前 Codex 提供 `open_in_codex` 工具，使用该工具打开返回的 URL；否则把 URL 告诉用户。
5. 面板通过 SSE 实时显示后续命令、上传、下载、部署、退出码和输出，并为每个操作显示“做了什么”摘要。
6. 面板左侧可以切换全部会话或任意单独会话。
7. 用户要求关闭时，调用 `ssh_operation_dashboard`，`action` 使用 `停止`。

实时面板只监听 `127.0.0.1`，并带随机访问令牌，不应上传到公网。

## 交互式 SSH 终端

用户要求“交互式终端”“持续会话”“连续执行命令”时：

1. 调用 `ssh_terminal_open`，传入已保存的服务器别名。
2. 默认模式下，打开终端前会确认一次；打开后终端输入直接发送到远程 shell。
3. 使用 `ssh_terminal_write` 发送命令，命令通常以换行符结尾。
4. 使用 `ssh_terminal_read` 读取新增输出。
5. 使用 `ssh_terminal_close` 关闭终端。

实时面板也提供交互式终端区域：选择服务器、点击连接、输入命令即可。

该终端是基于行输入的持续 SSH shell，适合 `cd`、环境变量、连续命令。全屏程序（例如 `vim`、`top`）可能无法完整渲染。

## 安全说明

- 密码、私钥口令和仓库密钥只保存在本机，MCP 工具不会返回这些内容。
- Windows 优先使用 DPAPI；受限 Windows 会话下使用当前用户 ACL 保护的密钥文件。
- 建议使用最小权限部署账户；自动化部署优先使用密钥认证或配置好的免交互 sudo。
- 默认的主机指纹策略是 `accept-new`，首次连接会接受新主机指纹。生产环境确认指纹后，建议改为 `strict`。
